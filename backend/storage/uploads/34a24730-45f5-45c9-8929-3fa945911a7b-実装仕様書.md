# AI Agent Platform NADA 仕様書

## 1. 概要

### 1.1 プロジェクト名

仮称：

**AI Agent Platform NADA**

社内でユーザーがGUIからAIエージェントを作成・公開・実行できるWebアプリケーションを構築する。

ユーザーはプログラミングを行うことなく、

* AIエージェントの作成
* LLMモデルの選択
* システムプロンプトの設定
* Skillの追加
* MCPサーバーの追加
* 公開範囲の設定
* エージェントとのチャット
* ファイル・画像の添付
* 複数エージェントによるSquadの作成
* 実行コスト・トークン・処理時間などの分析

を行えるようにする。

# 9. MCP

AgnoではMCPサーバーを`MCPTools`としてAgentのツール群に接続できるため、本システムではMCPをAgent Capabilityとして扱う。([Agno][3])

## 9.1 MCP登録

設定項目：

* MCP名
* 概要
* URL
* Transport
* 認証方式
* 認証情報
* 有効/無効

例：

```json
{
  "name": "GitHub MCP",
  "transport": "streamable-http",
  "url": "https://example.com/mcp",
  "enabled": true
}
```

---

## 9.2 MCPセキュリティ

MCPの認証情報はDBへ平文保存しない。

推奨：

```text
Application
    ↓
Secret Manager
    ↓
MCP Server
```

開発環境では環境変数でも可。


### パーソナル

作成者本人のみ。

```text

```

### AD管理グループ

指定したADグループのメンバーのみ。

```text

```

```text

    Server Management Agent

```

# 27. コスト計算

モデルごとに料金テーブルを管理する。

```text
Model
├── provider
├── model_id
├── input_price
├── output_price
└── currency
```

計算：

```text
Input Cost
= input_tokens × input_price

Output Cost
= output_tokens × output_price

Total Cost
= Input Cost + Output Cost
```

モデルの価格変更に備え、**実行時点の価格をExecutionへ保存する**。

# 33. 実行アーキテクチャ

Agent定義をDBから取得し、RuntimeでAgno Agentを生成する。

```text
Database
   │
   │ Agent Definition
   ▼
AgentFactory
   │
   ├── ModelFactory
   ├── SkillLoader
   ├── MCPFactory
   └── PermissionChecker
   │
   ▼
Agno Agent
```

例えば概念的には、

```python
agent = Agent(
    name=config.title,
    model=model,
    instructions=config.system_prompt,
    tools=[
        *skill_tools,
        *mcp_tools,
    ],
)
```

という構成にする。


```text

   │
```

```text
       │                   │                   │
    Agents              Squads             Skills
       │                   │                   │
       │              ┌────┴────┐              │
       │              │         │              │
       ▼              ▼         ▼              ▼
    Agent A        Agent A   Agent B        Skill A
    Agent B        Agent B   Agent C        Skill B
    Agent C
       │                   │
       └──────────┬────────┘
                  ▼
              MCP Tools
                  │

                  │

                  +
                  
             Dashboard
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
     Token       Cost      Runtime
```

## 設計上の重要ポイント

このシステムでは、**AgnoそのものをアプリケーションのDB/API層にしない**ことが重要です。

```text
❌ Frontend
      ↓
   Agno直接操作

⭕ Frontend
      ↓
   FastAPI
      ↓
 Domain Service
      ↓
 AgentFactory / SquadFactory
      ↓
    Agno
```

というレイヤーにします。

これにより、Agentの設定・権限・AD・Skill・MCP・監査ログ・コスト管理をアプリケーション側で一元管理できます。

また、Agnoの現在の設計では`Agent`、`Team`、`Workflow`が明確に分離されているため、今回の**Agent＝単体エージェント、Squad＝Team**という対応が自然です。([Agno][6])

特に今回の要件では、**「AgentをDB上の宣言的な設定として保存 → AgentFactoryで実行時にAgno Agentへ変換する」**設計を中核にするのがよいと思います。これなら、後からモデル追加、Skill、MCP、AD権限、Squad、コスト管理を追加しても構造が崩れにくいです。
